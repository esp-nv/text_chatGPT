# **Архитектура на системата — текущо състояние** 

## **<mark>Основен принцип</mark>** 

Системата няма да бъде направена само за програмиране или конкретна област. 

<mark>Тя трябва да може да се използва за:</mark> 

- програмиране; 

- <mark>езици;</mark> 

- <mark>математика;</mark> 

- <mark>бизнес;</mark> 

- <mark>други видове обучения.</mark> 

Тоест **областта на обучение не е част от основната архитектура** . 

# **<mark>V1 — Основна версия</mark>** 

<mark>V1 представлява</mark> **<mark>общата картина на обучителната система</mark>** <mark>.</mark> 

<mark>До момента сме завършили три основни концепции:</mark> 

```
V1
│
├── Student / Студент
├── Teacher / Преподавател
└── Course / Курс
```

## **<mark>1. Student / Студент ✅</mark>** 

За студента трябва да можем да виждаме какво се случва с неговото обучение по конкретен курс. 

### **<mark>Информация за курса</mark>** 

<mark>Студентът може да бъде:</mark> 

- записан; 

- <mark>обучаващ се;</mark> 

- <mark>завършил;</mark> 

- <mark>отказал се/прекратил.</mark> 

### **Progress / Напредък** 

<mark>Във V1 е обобщена стойност:</mark> 

```
7 / 10
70%
```

<mark>и можем да покажем:</mark> 

```
Remaining:
3 / 10
```

### **<mark>Attendance / Присъствие</mark>** 

<mark>Отделно от прогреса:</mark> 

`7 / 10 70%` <mark>Това е важно:</mark> `Progress ≠ Attendance` <mark>Студентът може например да има:</mark> `Progress:    70% Attendance:  90%` 

### **<mark>Оценки</mark>** 

<mark>Пазим:</mark> 

`Intermediate Grade / Междинна оценка Final Grade / Крайна оценка` <mark>Във V1 те са</mark> **<mark>обобщени стойности</mark>** <mark>.</mark> 

В V2 ще можем да изградим детайлна система за оценяване и част от тези стойности да станат изчисляеми. 

# **<mark>2. Teacher / Преподавател ✅</mark>** 

<mark>Преподавателят е самостоятелна концепция. Не го обвързваме директно с един курс. Избрахме:</mark> `Teacher │ │ N:M ▼ TeacherCourseInstance │ ▼ CourseInstance` <mark>Тоест:</mark> 

- един преподавател може да води много провеждания; 

- <mark>едно провеждане може да има повече от един преподавател.</mark> 

Пример: 

```
Иван
 ├── C# — 2026
 ├── Python — 2026
 └── C# Advanced — 2027
Мария
 ├── C# — 2027
 └── JavaScript — 2027
```

### **<mark>Какво НЕ правим във V1</mark>** 

<mark>Не записваме още: „Иван е преподавал тема LINQ.“ Това остава за V2, когато въведем теми и занятия.</mark> 

# **<mark>3. Course / Курс ✅</mark>** 

<mark>Тук направихме най-много уточнения.</mark> 

<mark>Основната идея е:</mark> 

**V1 Course е визитна карта на курса + обща информация за конкретното му провеждане и студентите.** 

## **<mark>Course / Курс</mark>** 

<mark>Самият курс съдържа обща информация:</mark> 

```
Name / Име
Code / Код
Description / Описание
Requirements / Изисквания
Level / Ниво
Language / Език
TotalTopics / Общ брой теми
```

#### <mark>Във V1</mark> **<mark>не описваме самите теми</mark>** <mark>.</mark> 

<mark>Например:</mark> 

```
C# Основи
```

`Total Topics: 10` <mark>Но не:</mark> `1. Variables 2. Classes 3. LINQ ...` 

<mark>Това е V2.</mark> 

# **<mark>CourseInstance / Провеждане</mark>** 

<mark>Разделихме</mark> **<mark>Course</mark>** <mark>от конкретното му провеждане. Например:</mark> `Course: C# Основи ↓ CourseInstance: C# Основи — 2026` <mark>Така един курс може да бъде провеждан многократно. Например:</mark> `C# Основи │ ├── Провеждане 2026 ├── Провеждане 2027 └── Провеждане 2028` <mark>И всяко провеждане може да има различна организация.</mark> 

# **<mark>Начин на провеждане</mark>** 

<mark>Имаме три основни възможности:</mark> 

```
Online / Онлайн
On-site / Присъствен
Hybrid / Смесен
```

<mark>Но взехме важно решение:</mark> 

#### **<mark>Hybrid не е задължително отделен специален тип данни.</mark>** 

<mark>При смесено обучение можем да имаме:</mark> 

```
Online
Capacity: 20
```

```
On-site
Capacity: 10
```

<mark>и системата разбира, че това е Hybrid.</mark> 

<mark>Това позволява статистика по начин на участие.</mark> 

# **<mark>Capacity / Капацитет</mark>** 

При смесено обучение потребителят може да определи отделни капацитети: 

```
Online:       20
On-site:      10
```

```
Total:        30
```

<mark>Това е по-добре от:</mark> `HybridCapacity: 30` 

<mark>защото знаем</mark> **<mark>как са разпределени местата</mark>** <mark>.</mark> 

# **<mark>Дни и период на деня</mark>** 

<mark>Във V1 решихме да пазим:</mark> 

### **<mark>Дни</mark>** 

<mark>Например:</mark> 

```

Wednesday / Сряда
```

### **<mark>Част от деня</mark>** 

```
Morning / Сутрин
Afternoon / Следобед
Evening / Вечер
```

<mark>Но</mark> **<mark>точните часове</mark>** <mark>остават за V2.</mark> 

# **<mark>Година и място</mark>** 

<mark>За конкретното провеждане във V1 можем да знаем:</mark> `Year: 2026` 

`City: Vidin / Видин` <mark>ако обучението е присъствено или смесено. Не навлизаме още в:</mark> `Building` 

```
Room
Address
```

<mark>освен ако по време на реализацията не решим, че са необходими.</mark>

## <mark>Това е много важно, защото вече имаме ясна граница между версиите.</mark> **<mark>V2 — Детайли на обучението</mark>** 

<mark>Ще добавим:</mark> 

`Subject / Предмет ↓ Topic / Тема ↓ Lesson / Занятие` <mark>Тогава например:</mark> `Total Topics = 10` <mark>от V1 ще се превърне в реални 10 теми. И:</mark> 

```

```

<mark>вече може да бъде</mark> **<mark>изчислен</mark>** <mark>, вместо просто въведен.</mark>

`Monday Wednesday Evening` <mark>Във V2:</mark> 

```
Monday

```

```
Wednesday
18:00 – 20:00
```

<mark>и конкретните занятия могат да имат реални дати и часове.</mark> 

## **<mark>V2 — Детайлно преподаване</mark>** 

<mark>Във V1:</mark> 

```
Teacher → CourseInstance
```

<mark>Във V2 можем да имаме:</mark> 

```
Teacher → Lesson
```

<mark>и да знаем:</mark> 

<mark>кой преподавател е водил конкретната тема/занятие.</mark> 

## **<mark>V2 — Детайлно присъствие</mark>** 

<mark>Във V1:</mark> 

```

7 / 10
70%
```

<mark>Във V2:</mark> 

```
Lesson 1 → Present
Lesson 2 → Present
Lesson 3 → Absent
...
```

<mark>и системата изчислява:</mark> `7 / 10 70%` 

## **<mark>V2 — Детайлни оценки</mark>** 

<mark>Във V1:</mark> `Intermediate: 5.25 Final: 5.75` 

<mark>Във V2 можем да имаме:</mark> 

```
Quiz
Assignment
Practical exam
Midterm
Final exam
```

и съответните оценки да се използват за изчисляване на междинната и крайната оценка. 

# **Най-важният архитектурен принцип, който излезе** 

<mark>Мисля, че това е едно от най-силните ни решения досега:</mark> **V1 описва общото състояние. V2 добавя реалните детайли, от които това състояние може да бъде изчислено.** 

<mark>Например:</mark> 

```
V1
Progress: 7 / 10
Attendance: 8 / 10
```

<mark>↓</mark> `V2 10 реални теми 10 реални занятия 8 присъствия 7 завършени` 

<mark>↓</mark> `Calculated Progress: 70% Attendance: 80% Remaining: 3`

1. Идея на приложението
Student Management System
Уеб приложение, чрез което администратор/учител може да:
o	добавя, редактира и изтрива ученици;
o	добавя курсове/предмети;
o	записва ученици в курсове;
o	вижда в кои курсове участва даден ученик;
o	вижда кои ученици са записани в даден курс;
o	въвежда оценки;
o	търси ученици;
o	филтрира по курс;
o	вижда обща статистика.
Това е естествено разширение на модела Student → Enrollment ← Course, който е стандартен начин за моделиране на many-to-many връзка чрез междинна entity. Microsoft също използва подобен модел в примерното си ASP.NET Core + EF приложение. G GitHub

4. Класовете
Student
public class Student
{
    public int Id { get; set; }

    public string FirstName { get; set; }

    public string LastName { get; set; }

    public string Email { get; set; }

    public DateTime BirthDate { get; set; }

    public ICollection<Enrollment> Enrollments { get; set; }
}
Course
public class Course
{
    public int Id { get; set; }

    public string Name { get; set; }

    public string Description { get; set; }

    public int TeacherId { get; set; }

    public Teacher Teacher { get; set; }

    public ICollection<Enrollment> Enrollments { get; set; }
}
Enrollment
public class Enrollment
{
    public int Id { get; set; }

    public int StudentId { get; set; }

    public Student Student { get; set; }

    public int CourseId { get; set; }

    public Course Course { get; set; }

    public decimal? Grade { get; set; }

    public DateTime EnrolledDate { get; set; }
}
Teacher
public class Teacher
{
    public int Id { get; set; }

    public string FirstName { get; set; }

    public string LastName { get; set; }

    public string Email { get; set; }

    public ICollection<Course> Courses { get; set; }
}

4. Основната релация
Най-важното нещо, което ще демонстрираме:
             N                         N
       ┌───────────┐             ┌───────────┐
       │  Student  │             │   Course  │
       └─────┬─────┘             └─────┬─────┘
             │                         │
             │ 1                       │ 1
             │                         │
             │ N                       │ N
             └────────┐   ┌────────────┘
                      ▼   ▼
                  ┌───────────┐
                  │ Enrollment│
                  └───────────┘
Тоест:
един студент може да има много курсове
и
един курс може да има много студенти.
Enrollment е междинната таблица.
Това е много по-добре от сегашното:
public string Course { get; set; }
защото вместо да записваме примерно:
Course = "C#"
ще имаме истинска релация:
Student
   ↓
Enrollment
   ↓
Course

┌─────────────────────────────────────┐

│                                     │

„V1 беше първоначалният UI. При V2 запазихме съществуващата функционалност, но разработихме нов dashboard интерфейс. Потребителските настройки определят коя UI версия и тема да се зареди.“
Това вече показва мислене за backwards compatibility и user preferences, а не просто „смених дизайна“.

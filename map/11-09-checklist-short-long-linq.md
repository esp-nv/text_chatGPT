LINQ чеклист — long
1. Филтриране
Where(n => n > 10)

Чета го като:

Остави само елементите, за които условието е true.

При сложно условие:

Where(n => (n > 10 && n < 30) || n == 50)

Мисли на групи:

(A && B) || C

&& → и двете
|| → поне едното
2. Преобразуване
Select(n => n * 2)

Вземи всеки елемент и направи операцията с него.

Важно:

Where(n => n * 2 > 20)

→ смятането е само за проверка.

Select(n => n * 2)

→ смятането променя резултата.

3. Сортиране
OrderBy(n => n)

→ 1, 2, 3, 4

OrderByDescending(n => n)

→ 4, 3, 2, 1

Reverse() ≠ сортиране

Reverse → обръща съществуващия ред
OrderBy → създава сортиран ред

4. Вземане / пропускане
Take(3)

→ първите 3 от текущия резултат

Skip(2)

→ пропуска първите 2 от текущия резултат

Затова:

1,2,3,4,5
↓ Skip(2)
3,4,5
↓ Take(2)
3,4

5. Елемент
First           → първият / грешка при празно
FirstOrDefault  → първият / default при празно

Last            → последният / грешка при празно
LastOrDefault   → последният / default при празно

Single          → точно един / грешка при 0 или повече от 1
SingleOrDefault → 0 или 1 / грешка при повече от 1

Особено:

Single не означава „вземи един“.

Означава:

„Трябва да има точно един.“

6. Проверки
Any()

→ има ли поне един?

Any(n => n > 20)

→ има ли поне един, който отговаря?

All(n => n > 20)

→ всички ли отговарят?

Any → поне един
All → всички

Резултатът е bool.

7. Агрегиране
Count  → брой
Sum    → сума
Average → средно
Min    → най-малък
Max    → най-голям

Те обикновено връщат една стойност, а не колекция.

8. Колекции
Distinct()

→ уникални стойности, без да сортира

Concat(second)

→ първата последователност + втората

ToList()

→ получаваме List<T>

Как да четеш сложна LINQ заявка
Винаги:

Вход
 ↓
Where
 ↓

 ↓
Where
 ↓

Skip / Take
 ↓
First / Count / ToList и т.н.

Всеки метод работи върху резултата от предишния.

И при всяка стъпка си казвай:

„Какво влиза?“ → „Какво излиза?“

Това е най-силният ти инструмент при сложен LINQ.

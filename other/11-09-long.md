C# / LINQ — обобщение с примери и схеми
1. Value type vs Reference type
Value type
int a = 10;
int b = a;

b = 20;

Схема:

a → 10

b = a
↓
a → 10
b → 10

b = 20
↓
a → 10
b → 20

→ Копира се стойността.

Примери:

int
double
bool
char

Reference type
Person p1 = new Person();
Person p2 = p1;

Схема:

p1 ──┐
     ├──→ [ Person object ]
p2 ──┘

И двете референции сочат към един и същ обект.

p1 → Ivan
p2 → Ivan

Ако променим обекта през p2, промяната се вижда и през p1.

2. ref
void Change(ref int number)
{
    number = 50;
}

int x = 10;
Change(ref x);

Схема:

x
↓
[10]
↑
ref number

Методът работи със същата променлива, а не с копие.

3. out
Основната идея:

метод
  ↓
true / false
  +
стойност чрез out

TryParse
if (int.TryParse("123", out int number))
{
    Console.WriteLine(number);
}

Ако преобразуването успее:

TryParse → true
number   → 123

Ако не успее:

TryParse → false

out често се използва, когато методът трябва да върне успех/неуспех + стойност.

4. OOP — наследяване
class Animal
{
}

class Dog : Animal
{
}

Схема:

Animal
   ↑
   │ наследява
   │
  Dog

Dog : Animal означава:

Dog е наследник на Animal.

5. virtual + override
Базовият клас казва:

class Animal
{
    public virtual void Speak()
    {
        Console.WriteLine("Animal sound");
    }
}

Наследникът може да промени поведението:

class Dog : Animal
{
    public override void Speak()
    {
        Console.WriteLine("Woof");
    }
}

Схема:

Animal
Speak()
  ↓
общо/базово поведение

Dog
Speak()
  ↓
друго поведение → "Woof"

Запомни:

virtual  → позволява промяна
override → правя конкретното ново поведение

6. abstract class
abstract class Animal
{
    public abstract void Eat();
}

Наследникът трябва да реализира метода:

class Dog : Animal
{
    public override void Eat()
    {
        Console.WriteLine("Dog eats");
    }
}

Схема:

abstract Animal
       │
       ├── казва: "трябва да има Eat()"
       ↓
      Dog
       │
       └── реализира Eat()

7. Interface
Например:

interface IAnimal
{
    void Eat();
}

Класът го имплементира:

class Dog : IAnimal
{
    public void Eat()
    {
        Console.WriteLine("Dog eats");
    }
}

Мисли за interface като за:

договор — „ако ме имплементираш, трябва да предоставиш това поведение“.

Схема:

Interface
   ↓
какво трябва да има

Class
   ↓
как точно ще го направи

8. Casting
Animal animal = new Dog();

Реалният обект е:

Dog

но референцията е:

Animal

Схема:

Animal reference
       │
       ↓
   [ Dog object ]

Затова:

animal.Bark();

може да даде compile error, ако Bark() не съществува в Animal.

Защото компилаторът гледа типа на референцията при достъп:

Animal → няма Bark()

13. Property

17. Generic constraint

Това е constraint = ограничение.

То казва:

Схема:

↓

31. IEnumerable<T>
Най-просто:

нещо, което можем да обходим едно по едно.

IEnumerable<int> numbers

означава:

sequence от int
↓
може да бъде обхождан

Например:

foreach (var n in numbers)
{
    Console.WriteLine(n);
}

Връзката с List
List<int>
   ↓
може да бъде разглеждан като
   ↓
IEnumerable<int>

List има повече възможности:

Add()
Remove()
RemoveAt()
[индекс]
Count

Докато IEnumerable е по-общо и основната идея е:

"мога да обхождам това"

32. Deferred execution
Това е важно за LINQ.

var result = numbers.Where(n => n > 15);

Тук заявката обикновено не се изпълнява веднага.

После:

numbers.Add(40);

и при:

foreach (var n in result)

Where вижда и 40.

Схема:

Where()
  ↓
"ще те изпълня по-късно"
  ↓
numbers се променя
  ↓
foreach
  ↓
изпълнение

33. ToList()
var result = numbers
    .Where(n => n > 15)
    .ToList();

Тук:

Where
 ↓
изпълнява се сега
 ↓
ToList
 ↓
създава реален List

Ако след това:

numbers.Add(40);

result няма автоматично да получи 40.

Схема:

numbers → [10,20,30]

Where → [20,30]

ToList
 ↓
result → [20,30]

numbers.Add(40)

numbers → [10,20,30,40]
result  → [20,30]

34. null
?.
person?.Name

означава:

person има обект?
       ↓
     да → вземи Name
     не → null

??
string name = person.Name ?? "Unknown";

Схема:

Name има стойност?
   ↓
 да → използвай Name
 не → "Unknown"

Тоест:

?? → "ако е null, използвай другото"

??=
name ??= "Unknown";

означава:

name == null?
   ↓
 да → name = "Unknown"
 не → нищо

Сравнение:

??  → избира стойност
??= → присвоява стойност

35. Nullable int?
Нормално:

int age = 20;

int не може да бъде null.

Но:

int? age = null;

може.

Схема:

int
→ само число

int?
→ число ИЛИ null

HasValue
age.HasValue

→ има ли стойност?

Value
age.Value

→ вземи стойността.

Не трябва да взимаме .Value, ако стойността е null.

36. default
Когато не намерим стойност при OrDefault, получаваме default за съответния тип:

int     → 0
bool    → false
string  → null
class   → null

Например:

numbers.ElementAtOrDefault(10)

Ако индекс 10 не съществува и е int:

→ 0

37. ElementAt / ElementAtOrDefault
numbers.ElementAt(1)

→ елементът на индекс 1.

numbers.ElementAtOrDefault(10)

→ елементът на индекс 10, а ако няма такъв:

→ default

Схема:

ElementAt
→ дай този индекс

ElementAtOrDefault
→ дай този индекс или default

38. Reverse
При List<T>:

numbers.Reverse();

→ променя самия списък.

преди:
10 20 30 40

след:
40 30 20 10

При LINQ Reverse() идеята е да получим обърната sequence.

Тук важното е да разпознаваш кой Reverse() използваме.

→ премахва всички елементи.

преди → [10,20,30,40]

след → []

1. Какво е EF Core?
EF Core (Entity Framework Core) е инструмент, който ни позволява да работим с Database (база данни) чрез C# objects (C# обекти), вместо постоянно сами да пишем SQL.
Най-просто:
C# приложение
     ↓
   EF Core
     ↓
   SQL
     ↓
 Database
Например имаме таблица:
Users
----------------
Id | Name | Age
----------------
1  | Ivan | 30
2  | Maria| 25
3  | Peter| 40
В C# можем да имаме:
class User
{
    public int Id { get; set; }
    public string Name { get; set; }
    public int Age { get; set; }
}
EF Core прави връзката:
Database Table          C# Class

Users            →      User
Id               →      Id
Name             →      Name
Age              →      Age
Това е основната идея.

2. Защо ни трябва EF Core?
Представи си, че искаме:
„Дай ми всички Users, които са над 30 години.“
Без EF Core можем да напишем SQL:
SELECT *
FROM Users
WHERE Age > 30;
С EF Core можем да изразим същата идея чрез C#:
var users = context.Users
    .Where(u => u.Age > 30);
Тук важното е да не учим кода наизуст.
Нека първо го разчетем.
context
   ↓
Users
   ↓
Where
   ↓
Age > 30
Тоест:
„Вземи Users от Database и остави само тези, при които Age е по-голямо от 30.“

Това е един от най-важните термини в EF Core.
DbContext → контекст към базата данни
Можеш да го мислиш като посредник между нашия C# код и Database.
        C#
         ↓
     DbContext
         ↓
      Database
Например:

Тук:
DbContext

„Този клас представлява връзката/контекста с Database.“
А:

казва:
„Имаме достъп до Users.“

1. ORM — Object-Relational Mapping
Термините
Object → Обект
Relational → Релационен / свързан с релационна база данни
Mapping → Съпоставяне / свързване
Следователно:
ORM = Object-Relational Mapping
Най-просто:
ORM е начин да свържем C# objects (обекти) с таблици в Database (база данни).
Това е основната идея.
________________________________________
2. Защо изобщо ни трябва ORM?
Нека си представим, че имаме база данни.
В нея има таблица:

-------------------------

-------------------------
1  | Ivan   | 30

Това е начинът, по който Database съхранява информацията.
А в C# можем да имаме:

И точно това съпоставяне е идеята на ORM.

Само ще го кажем малко по-точно:
ORM може да превърне данните от таблицата в C# обекти, с които програмата може да работи.
Например Database има:
Users
----------------
Id | Name
----------------
1  | Ivan
2  | Maria
ORM може да представи тези данни в C# като:
User object
Id = 1
Name = Ivan

User object
Id = 2
Name = Maria
Тоест:
Database                         C#

Users table
   │
   ├── Row 1  ───────────────→  User object
   │
   └── Row 2  ───────────────→  User object
И тук има една много важна идея
Таблицата не се превръща в един огромен обект.
Ако имаме:
Users
----------------
1 | Ivan
2 | Maria
3 | Peter
получаваме 3 User обекта:
User → Ivan
User → Maria
User → Peter
Това е част от това, което означава Object-Relational Mapping.

Но нека още не скачаме към Code First. Първо да изясним точно това, което каза.
Какво означава „да съответства“?
Имаме например:
C#                         Database

User                       Users
Id                         Id
Name                       Name
Age                        Age
Идеята на ORM е да знае:
„Този C# модел представлява тези данни в Database.“
Тоест не просто:
„Вземи каквото има в базата и направи обекти.“
А по-общо:
Имаме два модела на представяне на едни и същи данни и трябва да има съпоставяне между тях.
Точно това е Mapping → съпоставяне.
А за „първо база или първо код“
Тук има две възможни посоки:
Database → C# Model
Това е подходът Database First.
И:
C# Model → Database
Това е подходът Code First.
Ние няма да ги смесваме. Когато стигнем до тази тема, ще кажем ясно кой подход разглеждаме.

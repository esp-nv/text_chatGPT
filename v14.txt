⭐ Най-важният файл в началото — Program.cs
Това е файлът, който искам да разбереш много добре.
При съвременен ASP.NET Core може да изглежда примерно така:
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();

builder.Services.AddOpenApi();

var app = builder.Build();

if (app.Environment.IsDevelopment())
{
    app.MapOpenApi();
}

app.UseHttpsRedirection();

app.MapControllers();

app.Run();
На пръв поглед изглежда малко.
Но тук има много важни концепции.
________________________________________
🔍 Нека го разбием
1. WebApplication.CreateBuilder
var builder = WebApplication.CreateBuilder(args);
Това създава builder за нашето ASP.NET Core приложение.
Можеш да го мислиш като:
„Подготви ми Web Application и ми дай място, където да конфигурирам как ще работи.“
Тук ще конфигурираме:
o	services
o	configuration
o	logging
o	dependency injection
o	middleware
o	environment
________________________________________
2. builder.Services
builder.Services.AddControllers();
Това е много важно.
Services е мястото, където регистрираме зависимостите, които приложението ще използва.
Тук започва да се появява една от най-важните концепции в ASP.NET Core:
Dependency Injection
Не се притеснявай, ако терминът още не ти е ясен.
Ще го научим с практически пример.
По-късно например ще направим:
builder.Services.AddScoped<IStudentService, StudentService>();
Това казва на ASP.NET Core:
„Когато някой поиска IStudentService, дай му StudentService.“
Това ще стане много по-ясно, когато стигнем до Services.
________________________________________
3. builder.Build()
var app = builder.Build();
До този момент казваме:
„Ето как искам да бъде конфигурирано приложението.“
С Build() казваме:
„Добре, създай приложението според тази конфигурация.“
Получаваме:
WebApplication app
________________________________________
4. Middleware
След това:
app.UseHttpsRedirection();
Това е middleware.
Middleware можеш засега да го мислиш като стъпка през която минава HTTP заявката.
По-късно ще имаме нещо подобно:
Request
   ↓
HTTPS middleware
   ↓
Authentication middleware
   ↓
Authorization middleware
   ↓
Controller
   ↓
Response
Middleware е огромна част от ASP.NET Core.
Ще го изучим отделно.
________________________________________
5. MapControllers()
app.MapControllers();
Това казва:
„ASP.NET Core, използвай Controller-ите в приложението и техните routes.“
Например ако имаме:
[ApiController]
[Route("api/[controller]")]
public class StudentsController : ControllerBase
{
}
ASP.NET Core ще знае, че този Controller обработва определени HTTP заявки.
________________________________________
6. app.Run()
app.Run();
Това стартира приложението.
След него нашият API започва да слуша за HTTP заявки.

ASP.NET Core MVC не е само за Windows. Това е едно от важните предимства на ASP.NET Core.
Какво означава това?
С ASP.NET Core MVC можеш да разработваш уеб приложения, които се изпълняват на:
o	Windows
o	Linux
o	macOS
Например:
                    ASP.NET Core MVC
                           │
             ┌─────────────┼─────────────┐
             ↓             ↓             ↓
          Windows         Linux         macOS
             │             │             │
             └─────────────┼─────────────┘
                           ↓
                        Web App
Потребителят може да отвори приложението през браузър независимо дали използва Windows, Linux, macOS, Android и т.н.
Това е и причината да не трябва да мислим за ASP.NET Core MVC = Windows приложение.
А какво е MVC?
MVC означава:
M — Model
Данните и бизнес моделът.
V — View
Това, което потребителят вижда в браузъра — HTML страниците.
C — Controller
Посредникът, който получава заявката и решава какво трябва да се случи.
Browser
   │
   │ HTTP Request
   ↓
Controller
   │
   ├── Model / Database
   │
   ↓
View
   │
   ↓
HTML Response
   │
   ↓
Browser
И точно тази архитектура е много полезна за разбирането на ASP.NET Core.

Какво означава „Do not use top-level statements“?
Това определя как ще изглежда началният C# код на приложението.
При стандартния модерен C# имаме т.нар. top-level statements. Например Program.cs може да изглежда така:
var builder = WebApplication.CreateBuilder(args);

var app = builder.Build();

app.Run();
Няма:
class Program
{
    static void Main(string[] args)
    {
        // ...
    }
}
C# автоматично разбира, че тези команди са началната точка на програмата.
